TickTrek - Real-Time ARM Timer Game

Date: March 2026

Overview

TickTrek is a real-time, timer-driven game built on an ARM-based embedded system, where a player navigates a moving character across a 20×20 grid to collect points within a fixed time limit. The character moves automatically based on a hardware timer, while the player dynamically changes direction using keyboard input.

The project focuses on implementing precise timing behavior using hardware timers and interrupts instead of traditional software delays. The gameplay becomes progressively more challenging as the movement speed increases over time, requiring accurate synchronization between timer events, user input, and game logic.

Technologies & Tools

  • C Programming
  • ARM Assembly Language
  • Hardware Timers & Interrupts
  • UART / Keyboard Input Handling
  • Embedded Systems Development Environment

Key Features

  • Timer-Driven Movement: The character moves automatically at fixed intervals controlled by a hardware timer, ensuring consistent real-time behavior.
  • Real-Time Input Handling: Direction changes (W, A, S, D) are processed instantly using interrupt-driven input without blocking execution.
  • Dynamic Difficulty: Game speed increases every 5 seconds by reducing the timer period, making gameplay progressively more challenging.
  • Scoring System: Players collect numbers (1–9) to gain points, and collected items disappear to prevent reuse.
  • Pause & Resume: A hardware button pauses and resumes both gameplay and timer progression.
  • Game Termination: The game ends when the player collides with a wall or when the 20-second time limit is reached.

What I Learned

This project strengthened my understanding of real-time embedded systems and how hardware timers and interrupts are used to manage time-sensitive operations. One of the main challenges was coordinating multiple asynchronous components, including timer interrupts, user input, and game logic, without introducing delays or race conditions.

I also improved my debugging skills at the hardware-software interface, especially when dealing with timing inconsistencies. If I were to extend this project, I would modularize the code further and introduce additional gameplay features such as obstacles or multiple levels.

Results

The final system successfully implements a fully functional real-time game with accurate timer-based movement, responsive controls, and adaptive difficulty. All project requirements were met, including interrupt-driven execution and real-time score updates.

This project demonstrates my ability to design and implement interactive systems at the hardware-software boundary, with a strong focus on timing accuracy and system responsiveness.
